# Structured recipe format

Recipes are UTF-8 JSON using schema `1`. A release recipe declares:

- `id`: immutable release identifier;
- `game`: canonical game key;
- `accepted_sha1`: exact canonical inputs;
- `allow_modified_input`: whether a compatible randomized input may be used;
- `fingerprints`: invariant regions that must still match;
- `writes`: fixed-size expected/replacement byte pairs; and
- `canonical_output_sha256`: optional exact output check for canonical input.
- `configurable.level_caps`: optional named one-byte level sites generated by the
  recipe's fixed writes. Each entry has an `id`, byte `offset`, and `default`
  level from 1 through 100.
- `configurable.wipe_mode`: an optional one-byte mode site with an `offset`, a
  `default` of `forgiving` or `hardcore`, and distinct byte encodings for both.

Each fingerprint has a non-negative byte `offset` and `expected_hex`. Each write
adds `replacement_hex` of exactly the same length. Writes may not overlap or
extend the file. The patcher checks all regions against the original input before
writing anything.

This format intentionally cannot insert arbitrary files, run scripts, resize an
input, or silently overwrite bytes. A randomized input is accepted only if a
recipe opts in and provides invariant fingerprints in addition to per-write
expected bytes.

## User configuration

`quickloke-patcher apply --config CONFIG.json` accepts a UTF-8 schema-`1` object:

```json
{
  "schema": 1,
  "game": "yellow",
  "wipe_mode": "forgiving",
  "level_caps": {
    "surge": 24
  }
}
```

The game must match the recipe, each cap key must be declared by that recipe,
levels must be integers from 1 through 100, and `wipe_mode` must be `forgiving`
or `hardcore`. Forgiving restores the post-victory checkpoint from the previous
Gym after a full-party wipe. Hardcore permanently invalidates the run save after
a full-party wipe. Configuration changes only declared single-byte sites after
all fixed recipe writes have been validated. Unknown keys, duplicate sites,
inconsistent generated defaults, booleans, and out-of-range levels fail before
an output is published. Canonical output hashes remain mandatory for default
configuration; a genuine override necessarily produces a different reported
output hash.
